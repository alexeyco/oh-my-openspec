# Using both?

Skill ids match upstream exactly (`openspec-propose`, `openspec-apply-change`, …), so a project with `openspec init --tools opencode` alongside the plugin loads the same workflows — the plugin just keeps them current on every release instead of on every manual `openspec update`. The six commands this plugin adds (`/omos.init`, `/omos.plan`, `/omos.quick`, `/omos.apply`, `/omos.archive`, `/omos.retro`) and the upstream ones coexist: upstream skills are single-workflow steps, the flow commands are the multi-agent runs over the whole change. `/omos.quick` combines a short plan and apply for one bounded behavior; Codex exposes it as `$oh-my-openspec:omos-quick`. It stops before archive, which remains a separate `/omos.archive` or `$oh-my-openspec:omos-archive` action.
