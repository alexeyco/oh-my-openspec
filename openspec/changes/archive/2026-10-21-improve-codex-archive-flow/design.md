# Design

## Approach

Update `core/prompts.ts::archiveInstruction` and `codex/skills.ts::renderArchiveSkill` as the sources for Codex archive guidance: sync before archive, stop before archive on a sync blocker, then validate and repair fixable OpenSpec issues after archive. Keep `skills/omos-apply/SKILL.md` host-neutral with `/omos.archive <change-id>`; adapt it to `$oh-my-openspec:omos-archive <change-id>` only in the Codex flow renderer. Update the planner role contract for drafts and the archive sync behavior for new main specification files. Migrate machine-identifier titles in every existing main specification to readable titles; preserve already readable titles, paths, and all non-title content. Leave archive change artifacts and history unchanged.

## Files to touch

- `core/prompts.ts` — shared archive instructions for sync, archive, post-archive validation, and repair.
- `skills/omos-apply/SKILL.md` — retain the shared `/omos.archive <change-id>` recommendation.
- `codex/skills.ts::renderArchiveSkill` — render the Codex archive wrapper guidance from the shared archive instruction.
- `codex/skills.ts` — transform the shared apply recommendation to the Codex `$oh-my-openspec:omos-archive <change-id>` form and render other plugin-owned skill recommendations with namespacing.
- `tests/prompts.test.ts` — pin the archive instruction sequence and failure handling.
- `tests/assets.test.ts` — pin the shared apply recommendation and archive behavior.
- `tests/codex-skills.test.ts` — pin `renderArchiveSkill` guidance, the Codex renderer's apply conversion, and namespaced plugin mentions.
- `agents/omos-planner.md` — require human-readable `### Requirement:` names and readable titles when drafting capability specs, preserving technical identifiers and paths.
- `core/prompts.ts::archiveInstruction` and `codex/skills.ts::renderArchiveSkill` — title newly created main capability specs during sync and preserve existing authored titles.
- `openspec/specs/orchestration-flows/spec.md` — delta for archive completion and apply's archive next step.
- `openspec/specs/codex-host-integration/spec.md` — delta for namespaced Codex recommendations.
- `openspec/specs/agent-role-contracts/spec.md` — delta for readable generated specification headings.

## Decisions

- A required sync blocker stops the flow before archive; the archive step does not run on unsynced specifications.
- The post-archive validation loop may repair OpenSpec artifacts only. If a reported problem requires implementation changes or cannot be fixed safely, the flow stops and reports it.
- The shared apply source keeps `/omos.archive <change-id>`; `codex/skills.ts` adapts it to `$oh-my-openspec:omos-archive <change-id>` in Codex.
- Machine-identifier titles in existing main specifications are migrated to readable titles; already readable titles are preserved. Paths and non-title content remain unchanged.
- A newly created main specification gets a readable title derived from its capability purpose or meaning.
- Technical identifiers, capability directory names, and change IDs remain unchanged.
- `vendor/openspec/` remains generated by the existing vendor-sync workflow and is not edited by hand.
- `plugins/` remains generated by `make codex` and is not edited by hand.
- Archive change artifacts and historical archived specifications are outside the title migration.
