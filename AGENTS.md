# oh-my-openspec

Repo guide for AI agents working on this repository.
Human-facing docs: [README.md](README.md), [CONTRIBUTING.md](CONTRIBUTING.md).

## Conventions

- All content in English.
- No model pins anywhere — roles inherit the session model.
- `agents/*.md` is the single source of truth for role definitions.
  Frontmatter carries `description` and `mode: subagent` only.
- `core/` has no host imports — only Node builtins and `yaml`. The adapter
  imports from `core/`; `core/` never imports from `opencode/`.
- `codex/` may import `core/` and Node builtins, never the reverse —
  `core/` never imports from `codex/` or `plugins/`.
- `vendor/openspec/` is generated by `scripts/sync-vendor.mjs` — never edit
  by hand, never reformat (it is in `.prettierignore`).
- `plugins/` is generated by `make codex` — never edit by hand, never
  reformat (it is in `.prettierignore`; drift fails
  `tests/codex-bundle.test.ts`).
- Upstream OpenSpec owns spec validation: the plugin delegates to the
  `openspec` CLI (`openspec_validate` tool) and must not re-implement or
  fork its rules.
- The plugin never runs git write commands; committing belongs to the user.
- Never add promotional footers or badges — "Generated with X", "Powered by
  X", promo links — to PR bodies, issue bodies, commit messages, or any other
  outward-facing text, in this repo or elsewhere. Factual provenance lines are
  not ads: the vendor-sync workflow body's "Generated by the daily
  `vendor-sync` workflow" line is factual provenance — keep it.

Release: tag-driven npm publish — see [CONTRIBUTING.md](CONTRIBUTING.md#publishing).
